# ime_cursor

マウスカーソルの横に現在の IME の状態（ひらがな / カタカナ / 英数 など）を小さなバッジで表示し、あわせて**マウスカーソルの色とサイズ**も変えられる Windows 常駐ツールです。設定は付属の**管理画面**から行います。

日本語 IME の状態は画面右下のタスクバーにしか出ないため、視線を大きく動かさないと確認できません。カーソルに追従するバッジを出すことで、入力中の視線のまま状態が分かるようにします。

![ime_cursor のスクリーンショット](screenshot.png)

エディタで日本語入力中の様子。マウスカーソル（Ｉビーム）の右下に「あ」のバッジが追従しています。

## できること

| 機能 | 内容 |
| --- | --- |
| IME モード表示 | カーソル追従バッジ。管理画面のボタンで**オン / オフ**を切り替え |
| マウスカーソルの色 | プリセット 8 色 + 任意の色。**実行中のアプリにも即座に反映** |
| マウスカーソルのサイズ | 32〜256 px。**実行中のアプリにも即座に反映** |
| 既定に戻す | ツールを使う前のカーソル設定をそのまま復元 |

## 特徴

- **依存パッケージゼロ** — Python 標準ライブラリ（`ctypes` + `tkinter` + `winreg`）のみ
- **管理者権限不要** — 書き換えるのは `HKEY_CURRENT_USER` 配下だけ
- **再ログオン不要** — 色もサイズも、すでに起動しているアプリに即座に効く
- **クリックスルー** — バッジの上でも普通にクリックできる（マウス操作を一切邪魔しない）
- **フォーカスを奪わない** — `WS_EX_NOACTIVATE` 指定なので、入力中のアプリのフォーカスは維持される
- **高 DPI 対応** — Per-Monitor v2。複数ディスプレイ・スケーリング混在でも位置がズレない
- **ちらつき防止** — ウィンドウ切り替え中などに IME への問い合わせが一瞬失敗しても、直前の状態を保持する
- **元に戻せる** — 変更前のレジストリ値を退避してから適用する

## 動作環境

| 項目 | 内容 |
| --- | --- |
| OS | Windows 10 / 11 |
| Python | 3.10 以上（tkinter 同梱のもの） |
| 追加インストール | 不要 |

Microsoft Store 版 Python 3.13（tkinter 8.6 同梱）で動作を確認しています。

## 起動

### ダブルクリック

エクスプローラーで **`ime_cursor.pyw`** をダブルクリックすると、管理画面が開いて常駐します。`.pyw` は `pythonw.exe` に関連付けられているため、コンソール（黒い窓）は表示されません。

**常駐中にもう一度ダブルクリックすると、管理画面が前面に戻ってきます。** 多重起動にはならないので、管理画面を閉じたあとの呼び出しはこの操作で行ってください。

### コマンドから

```
pythonw ime_cursor.pyw                 管理画面を出して常駐する
pythonw ime_cursor.pyw --silent        管理画面を出さずに常駐する（自動起動向け）
python  ime_cursor.pyw --debug         GUI を出さず IME 状態をコンソールに出す
python  ime_cursor.pyw --reset-cursor  カーソルの色とサイズを既定に戻して終了する
python  ime_cursor.pyw --help          使い方を出す
```

### 自動起動（ログオン時）

1. `Win+R` → `shell:startup` を開く
2. `ime_cursor.pyw` のショートカットをそのフォルダに置く
3. ショートカットのリンク先の末尾に ` --silent` を足す（起動時に管理画面を出さない）

保存済みの色とサイズは、起動時に自動で適用し直されます（「[サイズが効く仕組み](#マウスカーソルのサイズ)」の理由から、サイズはサインアウトで失われるため）。

## 管理画面

![管理画面](screenshot-admin.png)

### IME モード表示

| 操作 | 内容 |
| --- | --- |
| **IME モード表示を開始 / 停止** | バッジのオン / オフ。押すとその場でマウスカーソル付近に出る / 消える |
| 表示中 / 停止中 | 現在の状態 |
| いまの IME | バッジと同じ内容を管理画面上でも確認できる |
| 半角英数・直接入力のときは隠す | 日本語入力中だけバッジを出したいとき |
| 説明も出す | 「あ」ではなく「あ ひらがな」と出す |
| 文字サイズ / 不透明度 | バッジの見た目 |

### マウスカーソルの色

「色を指定する」を選ぶか、プリセットの色ボタンを押すとその場で適用されます。「色を選ぶ…」で任意の色も指定できます。

「変更しない（Windows の設定のまま）」に戻すと、色だけを Windows の設定に返します（サイズの指定は残ります）。

### マウスカーソルのサイズ

スライダー（8 px 刻み）またはプリセットボタンで 32〜256 px。スライダーはドラッグ中ではなく、**離した時点**で適用します。

### 下部のボタン

| ボタン | 内容 |
| --- | --- |
| カーソルを既定に戻す | 色とサイズを、このツールを初めて使う前の状態に戻す |
| 管理画面を閉じて常駐 | ウィンドウを隠す。バッジと常駐は続く（× ボタンも同じ動作） |
| 終了 | 常駐を終了する。カーソルの設定はそのまま残る |

### ログ

適用した内容や失敗した理由が時刻付きで並びます。**「ログをコピー」**でクリップボードに入るので、うまく動かないときはそのまま貼り付けて共有できます。

## 終了

管理画面の「終了」ボタンで終了できます。管理画面を出していないときは、プロセスを終了させます。プロセスの**コマンドライン**にスクリプトのパスが入っているため、それを条件にこのスクリプトだけを狙って終了できます。

```
powershell -NoProfile -Command "Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -like '*ime_cursor.pyw*' } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }"
```

他の `.pyw` スクリプトを `pythonw` で常駐させていても、それらは終了しません。

タスクマネージャーから終了する場合は、「詳細」タブで列見出しを右クリック →「列の選択」→「コマンド ライン」にチェックを入れてください。どの `pythonw` がこのスクリプトなのか判別できます。

`taskkill /im pythonw.exe` のようなプロセス名だけの指定は使わないでください。他の `.pyw` スクリプトを巻き添えにするうえ、プロセス名は Python の導入方法によって `pythonw.exe` / `pythonw3.13.exe` と変わるため、そもそも当たらないことがあります。

## 設定ファイル

管理画面での変更は自動保存されます。手で編集する場合は、常駐を終了してから書き換えてください。

```
%USERPROFILE%\.ime_cursor\config.json     設定
%USERPROFILE%\.ime_cursor\cursors\*.cur   生成したカーソル画像
```

| キー | 既定値 | 説明 |
| --- | --- | --- |
| `badge_enabled` | `true` | IME モード表示のオン / オフ |
| `hide_alnum` | `false` | 半角英数・直接入力のときはバッジを隠す |
| `verbose` | `false` | 「あ ひらがな」のように説明も表示する |
| `font_size` | `16` | バッジの文字サイズ（px） |
| `alpha` | `0.85` | 不透明度（0.0 = 透明 〜 1.0 = 不透明） |
| `offset_x`, `offset_y` | `20`, `20` | カーソルからの表示オフセット（px）。負の値でカーソルの左上に出せる |
| `follow_cursor_size` | `true` | カーソルが大きいとき、オフセットも比例して広げる |
| `interval_ms` | `30` | 位置と状態の更新間隔（ミリ秒）。小さいほど追従が滑らかで、CPU 使用率は上がる |
| `cursor_color` | `null` | カーソルの色（`"#00a0ff"` 形式）。`null` なら Windows の設定のまま |
| `cursor_size` | `32` | カーソルのサイズ（px、32〜256） |
| `cursor_backup` | `{}` | 初回適用時のレジストリ値。「既定に戻す」で使う。**消さないこと** |
| `admin_geometry` | `""` | 前回の管理画面の位置 |

なぜ `%APPDATA%` ではなくユーザーフォルダ直下かというと、Microsoft Store 版 Python は `%APPDATA%` / `%LOCALAPPDATA%` への書き込みをパッケージ配下の `LocalCache` に転送してしまうためです。生成したカーソルのパスはレジストリに書いて他のプロセスから開かせる必要があるので、転送されない場所に置いています。

## 仕組み

### IME 状態の取得

1. `GetForegroundWindow` → `GetGUIThreadInfo` で、入力フォーカスを持つウィンドウを特定する
2. `ImmGetDefaultIMEWnd` で、そのウィンドウに対応する IME ウィンドウのハンドルを得る
3. `SendMessageTimeoutW` で `WM_IME_CONTROL` を送る
   - `IMC_GETOPENSTATUS` → IME のオン / オフ
   - `IMC_GETCONVERSIONMODE` → 変換モードのビットフラグ

変換モードのビット（`IME_CMODE_NATIVE` / `KATAKANA` / `FULLSHAPE`）の組み合わせから、ひらがな・カタカナ・全角英数などを判定します。

フォーカス側のウィンドウから取得できない場合は前面ウィンドウにフォールバックし、それでも失敗した場合は直前の状態を最大 8 回分だけ保持します（表示のちらつき防止）。

`SendMessageTimeoutW` に `SMTO_ABORTIFHUNG` とタイムアウト 120ms を指定しているため、応答しないアプリが前面にあってもツールが固まることはありません。

### オーバーレイ表示

tkinter のトップレベルウィンドウに、`SetWindowLongPtrW` で以下の拡張スタイルを付けています。

| スタイル | 目的 |
| --- | --- |
| `WS_EX_LAYERED` | 半透明表示 |
| `WS_EX_TRANSPARENT` | クリックスルー（マウス操作を透過させる） |
| `WS_EX_NOACTIVATE` | クリックされてもフォーカスを奪わない |
| `WS_EX_TOOLWINDOW` | Alt+Tab とタスクバーに出さない |

`interval_ms` ごとに `GetCursorPos` を読み、`GetSystemMetrics(SM_*VIRTUALSCREEN)` で仮想デスクトップの範囲にクランプしてから移動します。カーソルを大きくしているときはバッジがカーソルの下に隠れるため、`follow_cursor_size` が有効ならオフセットも比例して広げます。

### マウスカーソルの色

Windows は「マウスポインターの色」を `%SystemRoot%\cursors\*.svg` からその場でレンダリングし、`%LOCALAPPDATA%\Microsoft\Windows\Cursors\*_eoa.cur` に書き出しています。**レジストリの `CursorColor` を書き換えるだけでは何も起こりません**（`SPI_SETCURSORS` はレジストリが指すファイルを読み直すだけで、画像を再生成しない）。

そこで、Windows 自身と同じことを自前でやります。

- 「Windows Aero」スキームの `aero_*.cur` / `aero_*.ani` は、白い本体と黒い縁取りだけのグレースケール画像になっている
- 各ピクセルの輝度に目的の色を掛ければ、白 → 指定色 / 黒 → 黒 となり、Windows 純正の着色結果と一致する
  （実測: 輝度 255 × 色 250 ÷ 255 = 250、輝度 96 → 94 と Windows の出力に一致）
- `.ani` は RIFF/ACON なので、`icon` チャンクごとに同じ処理をかける
- Aero スキームはテキストカーソルと十字カーソルを持たない（OS 内蔵のモノクロ版が使われる）ため、この 2 つだけは同じ見た目になるよう自前で描く

着色は `bytes.translate` による変換表 1 回で済むので、17 種類ぶんで 0.2 秒ほどです。生成したファイルは `%USERPROFILE%\.ime_cursor\cursors\` に置き、レジストリの `HKCU\Control Panel\Cursors` からそこを指させます。

Windows 側の配色機能（`HKCU\Software\Microsoft\Accessibility\CursorType`）は 0 に倒します。有効なままだと、再ログオン時にこちらのスキームが上書きされることがあるためです。

### マウスカーソルのサイズ

`HKCU\Control Panel\Cursors\CursorBaseSize` を書いて `SPI_SETCURSORS` を投げる、というよく紹介される方法では**すでに起動しているアプリのカーソルは大きくなりません**。`SM_CXCURSOR` がプロセス起動時にキャッシュされるためです（実測: `CursorBaseSize` を 32 → 96 → 256 と変えても、同一プロセスから見た `SM_CXCURSOR` は 64 のまま）。

そこで、寸法を直接指定してカーソルを載せ替えます。

1. `LoadImageW(NULL, パス, IMAGE_CURSOR, 幅, 高さ, LR_LOADFROMFILE)` で、指定サイズのカーソルを読み込む
2. `SetSystemCursor(ハンドル, OCR_*)` でセッション全体に載せる

これは即座に、全プロセスに効きます。ファイルの指定がない種別（Aero スキームのテキスト・十字カーソル）は、`LoadCursorW` + `CopyImage` で OS 内蔵カーソルの指定サイズのコピーを作って使います。

`SetSystemCursor` で差し替えられるのは標準の 14 種類（`OCR_NORMAL` など）です。手書き・場所の選択・ユーザーの選択の 3 種類には対応する `OCR_*` が無いため、こちらはレジストリ経由（再ログオン後に反映）になります。

`SetSystemCursor` の効果はサインアウトすると失われるので、`CursorBaseSize` も併せて書いて再ログオン後の初期値をそろえ、さらに常駐プロセスの起動時に設定を適用し直します。

### 元に戻す仕組み

初めて色・サイズを適用する直前に、`HKCU\Control Panel\Cursors` の 17 種類のパス・`CursorBaseSize`・`Scheme Source`・スキーム名と、`HKCU\Software\Microsoft\Accessibility` の `CursorType` / `CursorColor` を読み出し、`config.json` の `cursor_backup` に退避します。「カーソルを既定に戻す」はこれを書き戻し、`SPI_SETCURSORS` でレジストリから読み直させます（`SetSystemCursor` で載せたものもここで捨てられます）。

退避を取り直すときに自前の生成先を指しているエントリは「値なし（削除）」として扱うので、`config.json` を消してしまっても、自前のカーソルが「元の状態」として記録されることはありません。

管理画面が開けない状況では、コマンドラインから戻せます。

```
python ime_cursor.pyw --reset-cursor
```

## ファイル構成

```
ime_cursor.pyw          起動用（ダブルクリックする対象）
imecursor/
  win32.py              Win32 API (ctypes) の共通定義
  imestate.py           IME の状態取得
  config.py             設定ファイルの読み書き
  curfile.py            .cur / .ani の着色と生成
  cursortheme.py        カーソルの色・サイズの適用（レジストリ）
  overlay.py            カーソル追従バッジ
  admin.py              管理画面 (tkinter)
  app.py                起動制御（単一インスタンス・コマンドライン引数）
```

多重起動すると同じバッジが 2 枚重なるため、名前付きミューテックスで 1 プロセスに制限しています。2 回目以降の起動は目印ファイル（`%USERPROFILE%\.ime_cursor\show_admin.flag`）を置いてすぐ終了し、常駐している側がそれを見て管理画面を出します。

## デバッグ

`--debug` を付けると、GUI を出さずに状態遷移だけをコンソールへ出力します。このときは `pythonw` ではなく `python` で起動してください（`pythonw` は `sys.stdout` が `None` になり、`print()` が破棄されるため）。

```
python ime_cursor.pyw --debug
```

```
IME 状態を監視中 (Ctrl+C で終了)
あ  ひらがな     open=1 mode=0x09
A  直接入力     open=0 mode=0x00
```

`mode` は `IMC_GETCONVERSIONMODE` の生の値なので、判定がおかしいときはこの値を見てください。

カーソル関係の不調は、管理画面のログ欄に理由が出ます。「ログをコピー」で持ち出せます。

## トラブルシューティング

**バッジが「?」のまま**
IME ウィンドウが取得できていません。UWP アプリなど IMM32 を経由しない一部のアプリが前面にあると発生することがあります。別のアプリにフォーカスを移すと復帰します。

**ダブルクリックしても何も起きない**
`.pyw` が `pythonw.exe` に関連付けられていない可能性があります。次のコマンドで確認してください。

```
reg query "HKCU\Software\Classes\.pyw"
```

関連付けが無い場合は `pythonw ime_cursor.pyw` で直接起動するか、`pythonw.exe` を指すショートカットを作成してください。

**管理画面が見つからない**
`ime_cursor.pyw` をもう一度ダブルクリックすると前面に出ます。

**カーソルの色が一部だけ変わらない**
手書き・場所の選択・ユーザーの選択のカーソルは `SetSystemCursor` で差し替えられないため、反映は再ログオン後になります。

**サインアウトしたらカーソルのサイズが変わった**
`SetSystemCursor` の効果はセッション内だけです。常駐プロセスを自動起動に登録しておけば、ログオン時に適用し直されます。

**カーソルを元に戻したい**
管理画面の「カーソルを既定に戻す」、または `python ime_cursor.pyw --reset-cursor` を使ってください。

**バッジの位置がカーソルとズレる**
Per-Monitor v2 の DPI 認識に失敗している可能性があります。`offset_x` / `offset_y` で調整してください。

## WSL から使う場合

スクリプトを WSL 側に置いたままでも、UNC パス経由で Windows の `pythonw.exe` から実行できます。

```bash
powershell.exe -NoProfile -Command "Start-Process pythonw -ArgumentList '\\wsl.localhost\<ディストリ名>\<スクリプトのパス>\ime_cursor.pyw'"
```

## 補足

`# /// script` の PEP 723 ヘッダを残してあるため、`uv run ime_cursor.pyw` でも起動できます。ただし `uv.exe` はコンソールアプリのため、ショートカットから起動すると黒い窓が出たままになります。uv を使う場合は、コンソールを持たない `uvw.exe` を利用してください。
